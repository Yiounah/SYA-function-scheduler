# SPEC — 任务规划时间轴

status: accepted-for-implementation  
date: 2026-10-26
source: SYA-UI BMAD (`bmad-spec` kernel) · user design handoff · SCH-001 / SCH-002 / SCH-003  
repo: `SYA-function-scheduler` (SYA-UI submodule `function/scheduler`)

## Why

研究者要把一个跨学期的长程课题拆成可见的阶段和下一步。当前 FocusFlow 两栏「目标 / 树」无法表达时间顺序、当前里程碑和清单执行。用户提供的桌面设计把同一棵任务树呈现为「课题 → 时间轴 → 子任务 → 清单」。

## Capabilities

- CAP-1: 用「新建规划」提交长程目标、期限与粒度，先生成可审阅草案，再由用户确认。旧 `tasks.init` 保留兼容；`accepted` 仅代表受理，不能作为规划成功的证据。
- CAP-2: 根节点为课题；一级子节点为时间轴阶段（SCH-003）。
- CAP-3: 选中阶段后展示子任务；选中子任务后展示清单，并用既有 `PATCH /api/v1/tasks/{id}/status` 更新叶子。
- CAP-4: 日、周（研究周报）、月三种导航共用同一份排期；进度来自叶子完成比例。
- CAP-5: 顶栏搜索过滤当前课题内的阶段与子任务标题。
- CAP-6: 多个课题同时存在。新建规划追加，不覆盖。侧栏只切换课题；「修改规划」只重拆该课题尚未开始的分支。
- CAP-7: 每个课题按自己的期限铺开叶子，再放进共用工作时段。同一分钟只排一个课题。
- CAP-8: 记录实际处理时刻。至少两次落在当前可工作时间之外时，建议新的每天工时和工作时段。用户接受后只重排完成时间。
- CAP-9: 粒度调整先预览指定任务的未开始部分，再由用户确认。细化和合并保持四层树、来源关系和已执行记录；日周月读取同一份保存的排期。

## 2026-10-26 粒度与作息完善

本轮仅修改 Scheduler 及主 APP 的 Scheduler 界面。粒度可指定目标分钟：更细 5–30、标准 25–60、更粗 45–120；默认分别为 25、45、90。按分钟进行工作分段及同父相邻合并，不声称生成新的语义子目标。保留总预计分钟、来源、四层结构、正在进行和已结束的内容；没有变化时禁用采纳并由服务端拒绝空提交。预览展示前后数量、总量与逐项变化。

作息新增专注、短休息、周期恢复及生效日期。工作、短休息、恢复分别标识；休息占用实际时间但不充当任务。生效前安排和已执行记录受到保护，预览展示前后节拍、受影响任务及截止溢出。日周月继续只读取服务器结果，旧工作事件字段保持兼容，休息通过独立 `breaks` 返回。

持续专注的评估说明见 `docs/scheduler-guide.md`。本轮没有实现跨模块专注评分器；完成率仅计 DONE，跳过和无样本不能成为成功或持续专注的证据。已有 `procrastination_index` 仅表示有记录的时长超支，不能作为心理状态判断。

## Constraints

- 保持 OpenAPI 根契约与既有 operationId 兼容，不新增 sidecar 端口，不把凭证暴露给渲染层。无项目参数时兼容活动树；新界面显式指定项目，跨课题日历使用 `projectId=all`。
- 课题、作息和今日粒度写入 `SYA_SCHEDULER_DATA_DIR/planner.json`。未设置该变量时，独立窗口使用 `~/Library/Application Support/sya-ui/scheduler`，与 SYA-UI 宿主是同一份文件。服务未配置数据目录时为内存模式；配置了目录但保存失败时返回错误，不宣称已持久化。不同课题用稳定的颜色框标注。
- 服务端保存任务日期、排期起点和带时区的时间块。进入规划前确认每天工时、工作时段和课题粒度。配置了午饭、晚饭时不计入工时；开始必须早于结束，配置的每日工时必须与扣除用餐后的可工作分钟一致。作息预览展示受影响任务，确认失败保留原作息和计划。
- 在可用工作时段内分配任务，扣除用餐与确认的休息周期。课题叶子以期限分布作为期望日期，容量不足时顺延并标记截止风险；不通过侵占休息或虚构每日产能来满足期限。每日可用工时与扣除用餐后的窗口必须一致。
- 修改课题不重拆已完成任务，也不动其它课题。任务拆解用英文；界面为中文时翻译显示，切回英文显示原文。
- 今日粒度的建议由用户决定是否采纳。更细把未开始清单拆成同级小步；更粗合并同一子任务下的未开始清单，不把清单变成第五层。正在执行及已完成的节点受到保护。Monitor 黄色入口保留原 taskId、reason 和真实 Focus session ID，活动任务不可拆时可预览其同组剩余步骤，没有可调步骤时明确提示。
- 界面语言为简体中文。证据以源码服务测试为主，不声称已打包安装验证。

## Non-goals

- SCH-004 桌面小组件、SCH-005 优先级、SCH-007–009 父应用 Dashboard 入口。
- 外部日历同步、日历拖拽改期、个人作息学习和自动冲突优化仍属于后续工作。多课题可以保存在与 SYA-UI 共用的计划文件里。

## 2026-10-26 对接补充（S1–S8）

本次用户明确采纳《Schedule_闫羽_补充实现与API对接》中的 MVP 要求，扩展原先仅限独立时间轴的范围；保留原 SCH 编号，不将父项目其它功能自动视为已交付。

- S1/S2：四层树显式区分项目与任务；日、周、月共用 `timeline.get` 的真实时间数据，浏览和切换项目不改活动树或复制任务。
- S3/S4/S5：`granularity.preview` 与 `routine.preview` 返回草案；Monitor 黄色路径和手动入口复用确认流程，取消不写正式计划。
- S6：`plans.preview` 不写正式树；`plans.commit` 校验 `expectedRevision` 与幂等 `requestId`。旧版本、过期草案、被取消草案及复用到其它草案的请求编号均被拒绝。任务状态与作息修改也推进版本。正式树、进度、排期、配置和已确认请求回执在配置的数据目录持久化。
- S7：主 APP 通过 Focus owner 开始、暂停、恢复和结束会话。结束计时不代表完成任务，不创建第二套会话编号。Deep Search 从 Scheduler 回读任务，恢复操作返回 Focus；Gatekeeper 读取需要的任务上下文。
- S8：展示生成中、取消、错误与重试；示例需主动选择并标识。记录生成、确认、粒度请求/采纳及任务完成事件，拒绝不计为采纳。

`tasks.init/revise/status` 的原始 EventAck 与 `/api/scheduler/*` 的 FunctionResponse 保持各自形状，由父项目 artifact adapter 适配。正式发布仍需独立提交、父仓库 gitlink 更新及发布产物验收。

## Success signal

桌面窗口打开后可完成：确认作息 → 新建规划 → 看到阶段 → 选中阶段查看子任务 → 勾选叶子并反映进度。多个课题可以并存。`npm test` 通过，界面品牌为「任务规划」。
